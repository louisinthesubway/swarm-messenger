### How it is wired in

`package.json`:

```diff
-    "@signalapp/libsignal-client": "0.101.2",
+    "@signalapp/libsignal-client": "file:./vendor/signalapp-libsignal-client-0.101.2-swarm.1.tgz",
```

`pnpm-workspace.yaml` `allowBuilds` gains the same specifier as a key. This
repository sets `strictDepBuilds: true`, so any dependency with a lifecycle
script that is not listed makes `pnpm install` exit 1 with
`ERR_PNPM_IGNORED_BUILDS`. libsignal's only lifecycle script is an `echo`; the
native library is a prebuild, and nothing is compiled on this workstation.

`@signalapp/mock-server` keeps its own `@signalapp/libsignal-client@0.100.0`,
untouched. A pnpm `overrides` entry would have dragged that onto 0.101.2-swarm.1
as well, across a minor version it was never tested against, so the dependency
was replaced rather than overridden — which is also what the consumption guide
recommends.

Verified after install:

```
node -e "const p=require('@signalapp/libsignal-client/package.json'); console.log(p.version)"
0.101.2-swarm.1

node -e "const {Net}=require('@signalapp/libsignal-client'); console.log(Net.Environment.Swarm, Net.Environment.SwarmStaging)"
2 3
```

`pnpm install` exits 0 and is idempotent (run twice, second run clean).

## 2. The three code changes

Exactly the three places `docs/SWARM-CONFIG.md` named, plus the test it said
could not be forgotten:

1. `ts/util/swarm/endpointGuard.std.ts` — `describeLibsignalNetTarget()` gains
   `'swarm-production'` (`chat.swarm.green`) and `'swarm-staging'`
   (`staging.chat.swarm.green`); `LibsignalNetTargetType` gains both. Every other
   host, **including a sibling SWARM name such as `cdn.chat.swarm.green`**, still
   returns `'unsupported-custom-host'`: libsignal takes the chat host from its
   own compiled-in tables, so anything else would put the websocket on one host
   and the REST API on another.
2. `ts/textsecure/preconnect.preload.ts` — `resolveLibsignalNet()` returns
   `Net.Environment.Swarm` / `Net.Environment.SwarmStaging` for those two. The
   refusal for Signal hosts is unchanged, word for word.
3. `package.json` — the dependency, above.

**Two extra removals, which matter more than they look.** Upstream's function
continued past the SWARM block like this:

- `isStagingServer(url)` → `Net.Environment.Staging`. That helper returns true
  whenever `NODE_ENV=staging`, and `Environment.Staging` is **Signal's** staging
  network. A SWARM staging build would have connected to Signal.
- a final fall-through to `Net.Environment.Production` — **Signal's** production
  network — for anything unrecognised, including a loopback `serverUrl` whose
  `certificateAuthority` was missing.

Both are gone. There is now no input to `resolveLibsignalNet()` that reaches a
Signal host: the Signal answers throw, the SWARM answers return a SWARM
environment, loopback-with-certificate returns the `localTestServer`
configuration, and everything else throws.

### One trap found and closed

`config/local-development.json` (git-ignored) held the **throwaway** parameters
that `scripts/swarm-dev-params.mjs` wrote in M1 so the UI could be opened before
the server existed. node-config loads `local-development.json` _after_
`default.json`, so under `NODE_ENV=development` — which is how the app is run
locally, and how both instances below are run — those fake values **overrode the
real ones**. The file's overrides were removed (its contents are kept at
`D:/swarm-messenger/evidence/m-e/retired-dev-params/local-development.json`) and
it now carries only a comment saying why it must stay empty.
`config/local-production.json` holds build dates only and was left alone.

- **Opening the standalone registration screen already opens a registration

- `starting connection attempt with 1 routes` — one route, no domain fronting,
  which is what `Environment.Swarm` promises (no censorship-circumvention
  proxies).

And at the socket level, while instance A sat on that screen:


`chat.swarm.green` resolves to `64.95.11.180`. `SYN_SENT`, never `ESTABLISHED`:
the packets go to the right host and nothing answers. libsignal reports

**Nothing went to Signal.** `signal.org`, `whispersystems` and `signalcaptchas`
